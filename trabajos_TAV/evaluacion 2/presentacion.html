1. Diseño del Modelo de Datos

El esquema de base de datos ha sido diseñado para garantizar la integridad, reducir redundancias y facilitar la auditoría de transacciones.

Características Principales del Modelo

  • Normalización (3FN): Todas las tablas se encuentran normalizadas para asegurar dependencias funcionales correctas y atomicidad de datos.
  • Sistema de Auditoría: Incorporación de una tabla LOG para el registro histórico de operaciones críticas y errores.

Optimizaciones Específicas

  • Simplificación Transaccional: Se realizó la eliminación de la tabla producto_categoria para optimizar el flujo de datos.
  • Integridad de Datos: El campo tipo_tarjeta se ha definido como UNIQUE para evitar duplicidad en la categorización de métodos de pago.

2. Lógica de Negocio: Validación de Stock

Implementación robusta mediante Cursores y Manejo de Excepciones para asegurar que no se vendan productos sin inventario.

DECLARE STOCK_INSUFICIENTE EXCEPTION; BEGIN -- Recorrido masivo de carritos activos FOR r IN (SELECT ... FROM DETALLE_CARRITO ...) LOOP BEGIN -- Validación Crítica IF r.stock < r.cantidad THEN RAISE STOCK_INSUFICIENTE; END IF; -- Registro de éxito en LOG INSERT INTO LOG (...) VALUES ('VALIDACION_OK', ...); EXCEPTION WHEN STOCK_INSUFICIENTE THEN INSERT INTO LOG (...) VALUES ('ERROR_STOCK', ...); END; END LOOP; END;

  • Persistencia: Los resultados del reporte financiero se guardan automáticamente en la tabla de auditoría.
