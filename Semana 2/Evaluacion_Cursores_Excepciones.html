Evaluación: Cursores y Excepciones

Auditoría Cruzada y Lógica Robusta PL/SQL

Descripción de la Actividad

En esta evaluación, continuaremos trabajando sobre los proyectos de base de datos (Crunchyroll, MercadoLibre, Steam), pero con un giro fundamental: La Auditoría Cruzada.

Ya no trabajarán sobre su propia base de datos. Deberán conectarse a la base de datos de un compañero, analizar su estructura y crear bloques PL/SQL avanzados para auditar, migrar o generar reportes complejos utilizando Cursores y asegurando la integridad con el manejo de Excepciones.

Cambio de Reglas: Todo el desarrollo debe realizarse sobre el esquema de base de datos de un compañero. ¡Coordine con su par para obtener accesos y comprender su modelo de datos!

Requerimientos de la Entrega

1. Análisis y Adaptación (Auditoría)

Antes de codificar, deben analizar el modelo de datos de su compañero. En su presentación deben explicar:

  • Qué tablas o procesos seleccionaron para trabajar.
  • Si encontraron errores de diseño o normalización (y cómo los manejaron en su código).
  • Cómo adaptaron su lógica a una estructura ajena.

2. Programación PL/SQL Avanzada

Deben implementar scripts PL/SQL que resuelvan una problemática de negocio (Ej: Recalcular totales, migrar datos históricos, generar reportes de auditoría, procesar colas de envíos, etc.).

2.1 Uso de Cursores (Procesamiento de Lotes)

Es obligatorio implementar al menos DOS de los siguientes mecanismos de cursores:

  • Cursor Explícito: Declaración, apertura, fetch y cierre manual para un control total.
  • Cursor FOR LOOP: Iteración simplificada para recorrido de registros.
  • Cursor con Parámetros: Reutilización de lógica de cursor para diferentes criterios.

Cada cursor debe procesar múltiples filas y realizar alguna operación lógica (no solo imprimir).

2.2 Manejo de Excepciones (Robustez)

El código NO debe fallar abruptamente. Deben capturar y gestionar errores:

  • Excepciones Predefinidas: NO_DATA_FOUND, TOO_MANY_ROWS, DUP_VAL_ON_INDEX, etc.
  • Excepciones Definidas por el Usuario: Crear sus propias excepciones para reglas de negocio (ej: SALDO_INSUFICIENTE, STOCK_AGOTADO).
Nota Importante: Se evaluará la creatividad en la solución. Un simple LOOP que imprime nombres no es suficiente. Deben modificar datos, insertar en tablas de log o realizar cálculos complejos fila por fila.

Pauta de Evaluación (Rúbrica)

Ponderación Total: 100%

Criterio Descripción Puntaje

Calidad del Material Presentación clara, diagramas explicativos del flujo del cursor y manejo de errores. 10%

B. Contenido Técnico (60%)

Criterio Descripción Puntaje

Excepciones Personalizadas Define y levanta (RAISE) excepciones propias para validar reglas de negocio específicas. 10%
Impacto en BD (Cross-Schema) El código efectivamente interactúa con las tablas del compañero (Select/Insert/Update). 10%

Entregables
